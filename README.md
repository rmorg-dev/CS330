# CS330 Reflection

## How do I approach designing software?
This project helped me break a larger project down into steps (developing objects, applying textures to objects, and applying lighting to objects) rather than trying to tackle it all at once. When determining how I designed my software, I made sure to go step by step. 
The biggest part of this was determining which primitive shapes to use in order to craft each object. I spent time thinking through each object and how to recreate this before beginning to think about the textures I was going to apply and the lighting. This required me to
think a bit outside the box for things I could not immediately implement (like the roof) with the shapes given. The tactics I learned designing this project will help me in future work by allowing me to think about a project in larger steps rather than only looking at a single 
object and trying to perfect it which may lead to a decrease in quality when getting to other objects in the scene.

## How do I approach developing programs?
While working on my 3D scene, I made sure to develop my code in steps, or iterations. For example, the first iteration was me building and scaling the basic primatives to fit the scene as close as possible. The next iteration was me applying textures to make the scene look
more realistic. The final iteration was me adding lighting effects to the scene to enhance the scene's details. My approach to developing code throughout the milestone evolved from trying complete all 3 aspects (building, texturing, and lighting) for each object, into 
trying to complete a single aspect for the entire scene. This helped me see the cohesion between the scene I was creating and the final scene I eventually submitted. 

## How can computer science help me in reaching my goals?
This class gave me more knowledge into how graphics work, as well as potential applications for things like linear algebra. It helped me gain the skills I need to make sure my projects are broken down into easy to complete steps and I do not focus too much on a single detail,
but rather the project as a whole.
